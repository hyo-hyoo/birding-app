## 当前阶段

产品需求澄清与 MVP 定义。

暂时不要进入代码实现、数据库设计、Rails Model、API、技术架构或高保真 UI 设计。

## 已确认

- 产品是面向普通用户、移动端优先的观鸟 Web App；
- 核心用户主要使用望远镜，没有照片或不希望依赖照片识别；
- 核心问题是保存会迅速消失的颜色、花纹和局部视觉印象；
- 第一阶段优先覆盖福冈日常、静态或低速活动中的鸟；
- 第一版以结构化输入为主；
- 用户选择大致轮廓，并对照标准侧面鸟体图记录特征；
- 第一版可记录部位为头部、胸腹、翅膀和尾部；
- 每个部位均为可选；
- 每个部位支持一个主颜色和一个可选补充色；
- 花纹和其他特征采用预设标签加可选文字补充；
- 确定程度采用三档：确定、大概如此、非常模糊；
- 系统生成抽象鸟类印象图和文字特征摘要；
- 用户可以修正、保存、重新打开和继续编辑；
- 第一版包含注册、登录和个人观察历史；
- 观察历史优先显示抽象图缩略图、确认状态和已确认鸟名；
- 当前低保真范围包含登录、注册、观察历史、轮廓选择、记录编辑、记录详情和设置七个页面；
- 登录后的主要导航包含观察历史、新建观察和设置；
- 登录前可在登录和注册页面切换显示语言，登录后在设置页面切换；
- 设置页面包含显示语言和退出登录；
- Ruby on Rails 仍是主要后端学习与开发方向。

## 正在讨论

- 轮廓模板的数量、分类层级和呈现方式；
- 颜色预设标签的具体集合；
- 花纹和局部特征预设标签的具体集合；
- 用户可以修正抽象图到什么程度；
- 鸟名的填写或选择方式；
- 待确认与已确认的状态变化；
- 观察时间、地点、环境和行为是否进入 MVP；
- 是否提供普通备注、语音输入或自然语言解析；
- 一条观察记录需要保存的最小信息；
- 注册成功后的最终去向；
- 底部导航的最终显示规则和未保存内容保护；
- 语言偏好的保存范围与切换反馈。

## 当前不做

- 自动推荐具体鸟种；
- 地区、季节和大规模分布数据库；
- 自动抓取网络昵称、梗和表情包；
- AI 自动搜索和整理网络文化内容；
- 用户投稿及内容审核；
- 社交功能；
- 复杂 AI 生图；
- 高自由度绘图工具；
- 微信小程序；
- Android 或 iOS 原生 App；
- 正式发布的 LINE MINI App；
- 一次性覆盖所有鸟类知识和识别能力。
