# 观鸟 Web App｜MVP 范围

> 文档状态：范围定义中  
> 本文档只定义第一版需要完成的用户闭环和明确排除项。  
> 具体产品需求见 `requirements.md`，尚未确认的想法见 `idea-dump.md`。

## 1. MVP 目标

完成一个用户可以实际操作和验证的完整闭环：

> 用户注册或登录后，新建一条观察记录，选择大致轮廓，通过标准侧面鸟体图记录自己观察到的颜色、花纹和确定程度，生成抽象鸟类印象图与特征摘要，修正后保存到个人观察历史，并在之后重新打开和编辑。

MVP 的价值在于保存一次尚未完成的辨认过程，而不是自动识别鸟种。

## 2. 当前拟纳入 MVP

### 2.1 已确认纳入

- 用户注册；
- 用户登录和退出；
- 个人观察历史；
- 新建观察记录；
- 选择鸟的大致整体轮廓；
- 使用标准侧面鸟体图作为记录参照；
- 用户自由选择要记录的身体部位；
- 第一版记录部位包括：
  - 头部；
  - 胸部与腹部；
  - 翅膀；
  - 尾部；
- 所有部位均为可选；
- 每个部位记录一个主颜色；
- 每个部位最多记录一个可选补充色；
- 使用主颜色和补充色表达混合颜色印象；
- 使用预设标签加可选文字补充记录花纹和其他可见特征；
- 使用三档确定程度：
  - 确定；
  - 大概如此；
  - 非常模糊；
- 根据结构化输入生成抽象鸟类印象图；
- 根据结构化输入生成文字特征摘要；
- 在输入或修改过程中更新生成结果；
- 用户修正已经填写的内容；
- 新建观察记录只有在已选择一个大致整体轮廓，并且至少一个身体部位记录了颜色、花纹或特征标签、自由文字描述中的任意一种有效特征后，才能保存；
- 保存到个人观察历史；
- 重新打开和编辑记录；
- 将记录标记为待确认或已确认；
- 已确认时显示鸟名；
- 观察历史优先显示抽象鸟图缩略图、确认状态和已确认鸟名；
- 设置页面；
- 登录前在登录和注册页面提供显示语言入口；
- 登录后在设置页面提供显示语言切换和退出登录；
- 登录后的主要导航包含观察历史、新建观察和设置。

### 2.2 暂定纳入，具体形式仍需确认

以下能力属于当前闭环的一部分，但具体范围尚未最终决定：

- 轮廓模板的数量、分类层级和呈现方式；
- 颜色预设标签的具体集合；
- 花纹与局部特征标签的具体集合；
- 抽象图允许用户修正到什么程度；
- 抽象图实时更新的具体交互方式；
- 鸟名的填写或选择方式；
- 待确认和已确认状态的具体转换规则；
- 注册成功后是否直接进入观察历史；
- 底部导航在哪些页面显示；
- 第一版显示语言暂定为简体中文和日本語；
- 设置页面暂定只包含显示语言和退出登录。

### 2.3 尚未决定是否纳入 MVP

以下内容具有价值，但当前尚未确认是否属于第一版：

- 观察时间；
- 观察地点；
- 周围生态环境；
- 鸟的行为；
- 普通备注或自由描述；
- 语音输入；
- 普通语音转文字；
- 自然语言自动提取结构化特征。

在形成明确结论前，不得自动加入开发任务。

## 3. 当前不纳入 MVP

- 根据地区和季节自动识别或推荐具体鸟种；
- 全日本或全球鸟类分布数据库；
- 大规模鸟类分布地图；
- 自动检索网络梗和表情包；
- AI 自动搜索和整理网络文化内容；
- 用户投稿及内容审核；
- 社交功能；
- 微信小程序；
- Android 原生 App；
- iOS 原生 App；
- 正式发布的 LINE MINI App；
- 复杂 AI 生图；
- 高自由度绘图工具；
- 一次性覆盖所有鸟类知识和识别能力；
- 完整 React 前端或完整 Vue SPA；
- 为少量飞行观察场景制作完整飞行鸟类记录系统；
- 草稿状态、草稿页面、自动保存及由此产生的额外保存工作流。

## 4. MVP 完成标准

MVP 只有在用户能够完成以下实际操作时，才视为完成。

### 4.1 账户与个人记录

1. 新用户可以创建账户。
2. 已有用户可以登录和退出。
3. 登录用户可以进入自己的观察历史。
4. 一个用户不能把其他用户的观察记录当作自己的记录查看或修改。

### 4.2 新建观察

5. 登录用户可以新建一条观察记录。
6. 用户可以从当前提供的视觉模板中选择一个最接近的整体轮廓。
7. 用户能够进入带有标准侧面鸟体示意图的记录界面。
8. 用户可以只选择自己看清楚的部位，不填写其他部位。
9. 用户可以独立记录头部、胸腹、翅膀和尾部中的任意一个或多个部位。

### 4.3 记录特征

10. 对每个已选择部位，用户可以选择一个主颜色。
11. 对每个已选择部位，用户可以选择一个可选补充色。
12. 用户可以选择预设花纹或特征标签。
13. 用户可以添加简短的自由文字补充。
14. 用户可以为已记录特征选择“确定”“大概如此”或“非常模糊”。
15. 用户可以不记录没有看清的部位。

### 4.4 生成和修正

16. 用户填写结构化特征后，可以看到一张对应的抽象鸟类印象图。
17. 用户可以看到一份只包含已填写内容的文字特征摘要。
18. 摘要能够表达各项特征的确定程度。
19. 系统不会为未填写的部位自行补全特征。
20. 用户修改结构化输入后，抽象图和摘要会相应更新。
21. 用户可以在保存前修正与记忆不符的内容。

### 4.5 保存、回看与确认

22. 用户只有在已选择一个大致整体轮廓，并且至少一个身体部位记录了颜色、花纹或特征标签、自由文字描述中的任意一种有效特征后，才可以保存观察记录。
23. 保存后，该记录会出现在用户自己的观察历史中。
24. 观察历史能够显示抽象鸟图缩略图。
25. 观察历史能够显示待确认或已确认状态。
26. 已确认记录能够显示鸟名。
27. 用户可以从观察历史重新打开记录。
28. 用户可以修改保存后的记录并再次保存。
29. 用户可以在日后为记录补充鸟种确认信息。
30. 完成上述流程不依赖照片、声音识别或自动鸟种推荐。

### 4.6 设置与语言

31. 用户可以在登录页面和注册页面切换显示语言。
32. 登录用户可以通过设置页面切换显示语言。
33. 登录用户可以从设置页面退出当前账户。

## 5. MVP 验证重点

MVP 完成后，优先验证：

- 用户是否能在约一至两分钟内完成核心视觉记录；
- 用户是否能够只填写看清楚的部位；
- 侧面鸟体图是否足以帮助用户定位部位；
- 少量轮廓模板是否能够覆盖福冈日常常见观察；
- 颜色和花纹标签是否足够表达真实观察；
- 抽象图是否有助于用户恢复当时的视觉记忆；
- 观察历史是否支持用户回家后继续辨认；
- 用户是否会因选项过多而产生混乱或被诱导补全记忆。
