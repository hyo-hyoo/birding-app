## 2. 目标与边界

### 2.1 本计划的完成目标

- 完成高保真基线中的 14 个 MVP 用户页面或流程状态；
- 使用 Rails Views、ERB、HTML、CSS、Rails I18n，以及必要的 Turbo、Stimulus 或少量普通 JavaScript；
- 简体中文和日文页面均可渲染；
- 主流程可通过真实 Rails 链接和本地交互连续检查；
- 完成桌面和移动端尺寸的浏览器验证；
- 为页面渲染、导航与重要局部交互提供自动化测试。

### 2.2 当前不包含

- 登录、注册、认证、邮件发送或密码更新的后端实现；
- Model、Migration、Schema 或业务数据持久化；
- 将预览示例数据升级为正式鸟类数据或业务配置；
- 营销首页、公开主页、社交、地图、推荐、管理员和其他非 MVP 页面；
- 内部“设计系统”参考页作为用户页面交付项；
- React、Vue、Tailwind、独立 SPA 或新的前端构建体系。

### 2.3 静态交互原则

- 表单可以填写和展示状态，但不向业务端点提交；
- 导航按钮应尽量连接到实际预览路由，不使用无效 `href="#"`；
- 轮廓选择、标签选择、编辑部位切换和确认对话框等局部行为可以使用 Stimulus；
- 浏览器刷新后允许预览状态重置，不要求持久化；
- 所有预览路由继续限制在 Rails 本地环境中。

### 阶段 5：观察记录详情与鸟种状态

**目标**

- 展示抽象图、摘要、各部位确定程度、行动位置和行为；
- 覆盖待确认、候选中和已确认三个详情状态；
- 展示最多三个候选鸟名的增加、选择和删除状态；
- 展示选择候选、输入其他最终鸟名、修改和撤销确认的页面状态；
- 接通返回历史和编辑记录。

**已确认返修标准（2026-08-16）**

- 防误操作根据数据丢失风险和操作是否可逆分别判断，不再让全部识别操作经过统一保存栏；
- 仅切换候选不产生未保存状态；
- 添加候选和确认最终鸟名由各自操作按钮直接生效，不显示第二个保存按钮；
- 删除普通候选和修改最终鸟名需要暂存、明确保存和未保存离开保护；
- 候选或其他最终鸟名输入框存在非空、尚未提交的文字时，离开页面需要先确认继续输入或放弃输入；
- 最终鸟名仍在候选中时撤销立即生效；最终鸟名不在候选中时询问是否保留为候选，候选已满时由用户明确选择替换项，不静默删除名称；
- 修改最终鸟名时只显示一个预填输入框；
- 已确认状态继续保留候选鸟名，候选区域默认折叠；
- 正文底部不恢复重复的返回历史和编辑观察入口；
- 当前批次只实现静态 Rails 页面和交互预览，刷新后状态可以重置，不接入业务持久化或后端逻辑。

**阶段 5 验收后的实现状态边界**

- 阶段 5 已通过整体用户验收；当前候选折叠入口、弹窗文案、按钮层级和满额替换候选的视觉表现仍属于 Observed-only／暂定静态实现细节，不因此成为最终 UI 规范。

**仍未确认依赖**

- 候选折叠入口的最终文案、视觉层级和展开控件尚未确认；
- “确认依据”字段是否进入 MVP 及其交互规则尚未确认，不得加入本阶段实现。

**返修实施结果（2026-08-16）**

状态：`已完成`

- 添加候选和确认最终鸟名改为由对应操作按钮直接生效，不再触发未保存标记或第二个保存按钮；
