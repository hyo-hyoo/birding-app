# 观鸟 Web App｜技术决策

> 文档状态：已确认技术路线
> 记录日期：2026-08-10
> 最近更新：2026-09-02
> 本文档只记录用户已经明确确认的技术与实施决定。产品能力以 `requirements.md` 为准，MVP 边界以 `mvp-scope.md` 为准，UI 状态以 `ui-design.md` 为准。
> 尚未经过安装、运行或测试验证的兼容性结论会明确标记为“实施时验证”，不得视为已经验证通过。

## 1. 总体架构

- 应用采用 **Rails 模块化单体**。
- 不建立独立 SPA、独立前端仓库或仅提供 JSON API 的后端项目。
- 前后端通过清晰的目录、职责和文件边界保持可独立修改，但共享同一个 Rails 应用、运行时和部署单元。
- Rails 后端学习仍是项目的主要技术重点；前端实现以可理解、可维护和足够完成 MVP 为准。

### 1.1 代码职责边界

- Model：数据关系、验证和核心业务规则。
- Controller：HTTP 请求、授权范围和流程编排，避免承载复杂业务规则。
- Service：只在注册验证、跨步骤保存等流程确实跨越多个对象时使用，不为简单 CRUD 创建形式化服务层。
- Presenter：组织文字摘要和 SVG 渲染所需的派生数据。
- Mailer 与 Job：分别负责邮件内容和异步执行。
- Rails View、局部模板、Stimulus Controller、CSS、I18n 和配置数据分别放在各自标准目录中。

MVP 不引入 Java 风格的 Repository／DAO 层，不引入 Pundit、CanCanCan 或 ViewComponent。个人数据访问通过当前用户作用域限制，例如从 `Current.user.observations` 查找记录，而不是直接按全局 ID 查找。

### 1.2 已确认的业务模块职责边界

以下名称用于说明 Rails 模块化单体中的业务职责，不要求创建同名 Ruby Module、Service、Model、Controller 或目录。产品规则由 `requirements.md` 拥有，实体、关联和约束的持久化映射由 `database-design.md` 负责。

#### Account／账户

- 负责用户身份、邮箱规范化与唯一性、密码摘要、密码规则、密码校验、邮箱验证状态和登录资格。
- 注册提交成功后立即创建未验证 User；未验证 User 不能登录。User 是 Session 和 Observation 的所有者。
- 使用 `has_secure_password`，只保存密码摘要。注册与账户流程由 Controller 编排，只有流程确实跨越多个对象并变复杂时才提取小型流程对象。
- 不负责登录 Session 的创建、续期或结束，不负责验证令牌、验证邮件与重发限流，也不负责 Observation、鸟种识别或表现生成。

#### Login Session／登录会话

- 每次成功登录创建一条属于 User 的独立数据库 Session；同一 User 可以同时拥有多个设备或浏览器会话。
- Rails 加密 Cookie 只定位当前 Session，数据库 Session 才是登录状态事实来源。Session 不保存 IP 或 User-Agent；负责恢复 `Current.session` 与 `Current.user`，并判断会话是否存在、有效或过期。
- Cookie 无法定位有效 Session，或 Session 已失效、已过期时，当前请求必须按未登录处理，不得只依据 Cookie 判断登录状态。
- 会话从登录成功时起固定有效 30 天，持续访问不自动续期；退出只结束当前浏览器的当前 Session。
- Session 不负责密码、邮箱验证、Observation 规则、locale 偏好或具体业务授权；个人数据仍由对应 Controller 从 `Current.user` 的关联集合查询。
- 邮箱验证流程中用于暂存待验证邮箱的加密浏览器状态属于 EmailVerification，不是数据库 Login Session，也不能恢复 `Current.user`。
- Session 退出或撤销时立即物理删除；过期时立即不可用，次日清理。完整数据保留边界见 6.8 节，物理映射见 `database-design.md`。

#### EmailVerification／邮箱验证

- 负责证明用户拥有注册邮箱，并只为未验证 User 管理验证流程；负责安全令牌、15 分钟有效期、最新链接与一次使用规则、验证状态更新及验证邮件重发限流。
- 负责区分有效、过期、无效、已使用和账户已经验证等令牌结果；这些结果必须由服务器根据正式状态判断。
- 注册结果页直接重发与重新输入邮箱重发共用同一流程、令牌规则、邮箱／IP 限流和统计；对外结果不得泄露邮箱是否存在。
- 验证成功后只更新 User 的验证状态并返回登录页，不创建登录 Session。验证结果必须由服务器判断，不能由查询参数或浏览器状态指定。
- 注册结果页暂存待验证邮箱的加密浏览器状态由 EmailVerification 管理，只用于衔接验证邮件流程，不代表用户已经登录。
- EmailVerification 决定是否允许发送、使用哪个令牌及业务结果；Mailer 只生成邮件内容和链接，Job 只异步执行发送。当前 locale 在入队时传给邮件任务。
- EmailVerification 与 PasswordReset 使用不同业务令牌，即使可以复用底层令牌工具、邮件样式或 Job 基础能力。

#### Observation／观察记录

- 是一次完整观察记录的聚合根，属于 User，负责新建、首次保存、历史与详情展示、编辑和再次保存的整体生命周期。
- 组织 PartImpression、ActivityLocationSelection 和鸟种识别相关数据；负责轮廓稳定键、首次成功保存时间、最后更新时间、可选行为文字等观察级业务含义。
- 新建过程中的输入只属于浏览器和表单临时状态；MVP 不创建草稿 Observation，只有满足最低保存条件并成功提交后才产生正式记录。
- 只有有效轮廓和至少一个有效 PartImpression 同时成立时才能产生正式记录；Observation、PartImpression 与 ActivityLocationSelection 在一次编辑提交中以同一数据库事务整体成功或失败。
- 鸟种候选和最终鸟名是保存后的独立识别操作，不与观察编辑表单共用事务。读取、编辑和更新必须从 `Current.user.observations` 开始查询。
- 不定义正式配置名单，不判断单个部位内部有效性，不生成或持久化 SVG／文字摘要，也不拥有鸟种识别的具体操作规则。
- MVP 当前不由 Observation 承担删除、软删除、删除恢复、版本历史、审计、自动保存或草稿管理职责。

#### PartImpression／部位印象

- 表示 Observation 内头部、胸腹、翅膀或尾部之一的结构化视觉印象，不能脱离 Observation 存在；同一 Observation、同一身体部位最多一条。
- 负责部位稳定键、主颜色、补充色、最多一个预设特征、自由文字和一档确定程度，以及单个部位是否有效的判断。
- 主颜色、预设特征或清理后的非空自由文字任意一项存在，才构成有效部位内容；有效部位必须有一档确定程度，只有确定程度不能创建记录。
- 无有效内容时不创建记录；编辑后清空全部有效内容时删除该部位记录并移除其确定程度。补充色依赖主颜色，清除主颜色时同时清除补充色，且主色与补充色不能相同。
- 自由文字在保存前移除首尾空白，只有空格、换行或制表符的内容视为空。默认打开头部编辑面板本身不能产生 PartImpression。
- 只保存颜色与特征稳定键，不保存本地化名称；不负责整条 Observation 的保存资格、行动位置、行为、识别、授权或表现生成。
- “同一 Observation、同一身体部位最多一条”需要 Rails 校验和数据库组合唯一约束共同保护；具体约束设计由 `database-design.md` 负责。

#### BirdIdentification／鸟种识别

- 依附于 Observation，负责候选鸟名、最终鸟名和由两者派生的识别状态；该职责名称不代表必须建立独立 `bird_identifications` 表。
- 每条 Observation 最多保存三个候选；候选和最终鸟名均由用户自由输入，系统不验证其科学准确性。最终鸟名可以与某个候选相同，两者仍承担不同职责。
- 鸟名按移除首尾空白后的内容提交；清理后为空不得保存，同一 Observation 不允许规范化后完全相同的重复候选。暂不自动合并同义词、别名、繁简体、日中名称或大小写。
- 没有候选和最终鸟名时为“待确认”，只有候选时为“候选中”，存在最终鸟名时为“已确认”；状态由数据派生，不由用户直接选择，也不单独持久化。
- 添加候选和确认最终鸟名提交成功后直接持久化；删除候选和修改最终鸟名采用暂存、明确保存和未保存离开保护。识别操作与观察编辑保存流程互不隐式覆盖。
- 仅切换当前选中的候选不改变业务数据。非空未提交鸟名、候选区域展开状态和弹窗状态属于浏览器工作状态，不持久化，但未提交鸟名需要离开保护。
- 已确认状态保留候选；修改视觉特征或删除一个同时也是最终鸟名的候选，不自动删除最终鸟名或取消确认。删除最后一个候选、撤销最终确认后的状态根据剩余候选和最终鸟名重新派生。
- 最终鸟名仍在候选中时撤销确认直接生效；不在候选中时先由用户决定是否保留为候选，候选已满时必须明确选择替换项，不能静默删除现有候选。
- 不负责自动推荐、鸟类数据库、图片、视觉特征、表现生成、Session 或 Observation 所有权判断；识别 Controller 先从 `Current.user.observations` 查找记录。

#### 辅助与跨领域职责

- 行动位置和行为文字属于 Observation 的补充信息，不建立独立顶层业务模块，并与 Observation、PartImpression 在同一观察编辑事务中保存。
- 轮廓、颜色、花纹／特征和行动位置属于版本控制配置；配置负责稳定键、顺序、适用部位、本地化名称关联和 SVG 映射，已经被记录引用的键必须保持可读取。
- SVG 与文字摘要是独立的服务器端派生职责；预览只读取未保存表单数据，不写入 Observation，SVG、摘要和缩略图均不持久化。
- Locale 是 Cookie 与 Rails I18n 的跨领域职责，不写入 User；邮件任务继承入队时的 locale。
- PasswordManagement 包含 PasswordReset 与 PasswordChange 的流程编排，Account 只执行密码规则并保存密码摘要；Mailer 与 Job 不拥有账户、令牌、限流或验证状态规则。

## 2. 开发与运行环境

- 开发环境使用 **Windows 原生环境**，不以 WSL2、Docker 或完整开发容器作为默认开发方式。
- 项目位于 Windows E 盘项目根目录 `E:\AAproject\birding-app`。
- Ruby：**4.0.6**。
- Rails：**8.1.3.1**。
- 数据库：**MySQL 8.4.10 LTS**。
- 第一阶段目标是先在本地完整运行、测试和演示；本地闭环完成后再准备部署。

以上版本组合已经完成实际安装、依赖解析、应用启动、MySQL 连接、`/up` 健康检查和基础测试验证；Windows 环境下 `mysql2` 已成功编译并连接 MySQL 8.4。后续新增 gems 和业务功能仍须在引入时继续验证，发现兼容问题时先报告具体证据，不得自行更换已确认版本。

## 3. Rails 初始化配置

项目采用普通 Rails 单体应用，并使用以下初始化方向：

- MySQL 数据库适配；
- Rails Views 与 ERB；
- Importmap；
- Propshaft；
- Turbo；
- Stimulus；
- Minitest；
- 保留 Action Mailer 和 Active Job。

MVP 初始化时跳过当前不需要的 Action Mailbox、Action Text、Active Storage、Action Cable 和纯 JSON API 组件。第一阶段不创建正式 Docker 和部署配置。

Rails 项目已经在仓库根目录初始化，并完成开发库、测试库准备和 `/up` 健康检查；这些基础验证不代表任何账户、观察历史或其他正式业务功能已经完成。

## 4. 前端实现路线

- 使用 Rails Views、HTML、CSS、Turbo、Stimulus 和少量普通 JavaScript。
- 页面导航、表单提交和服务器渲染优先使用 Rails 与 Turbo 的标准能力。
- Stimulus 只负责局部交互，例如语言菜单、编辑状态、预览触发和未保存修改提醒。
- 普通 JavaScript 只用于浏览器级能力或 Stimulus 不适合承载的极小逻辑。
- MVP **不引入 Vue**，也不引入 React 或独立前端构建体系。

当前交互主要是表单、局部替换、状态提示和结构化输入，没有达到需要 Vue 组件状态树或独立客户端数据层的复杂度。若以后确实出现无法由 Turbo 与 Stimulus 清晰维护的局部交互，必须重新说明需求和代价并取得确认，不能直接加入 Vue。

## 5. 抽象鸟类印象图

- 抽象图采用服务器生成的 **inline SVG**。
- SVG 由版本控制中的轮廓和部位映射配置，加上用户结构化输入生成。
- 预览请求不保存 Observation 或 PartImpression。
- Stimulus 触发预览请求，Turbo Frame 替换抽象图和本地化文字摘要。
- 实施顺序采用渐进方式：普通 Rails 预览提交 → Turbo Frame 局部替换 → Stimulus 自动触发。
- 数据库只保存结构化观察数据，不保存生成后的 SVG 文件、SVG 字符串或文字摘要。
- 历史和详情页面需要展示时，根据已保存的结构化数据重新生成 SVG 与摘要。

MVP 不采用 Canvas 作为主生成方案，也不使用 HTML/CSS 拼装完整鸟体。SVG 更适合少量固定轮廓、可定位身体部位、服务器渲染、响应式缩放和无损缩略图的当前需求。

## 6. 账户、认证与授权

- 使用 Rails 8 第一方 authentication generator 作为基础。
- 密码使用 `has_secure_password`。
- 服务端密码校验执行 8～20 个 ASCII 英文字母或数字、至少一个英文字母和一个数字的正式产品规则；不要求大小写同时出现。
- 登录状态使用数据库 Session 记录和 Rails 加密 Cookie，不采用 JWT；Session 不保存 IP 或 User-Agent。
- 登录会话最长保留 30 天，不提供“记住我”分支。
- 用户主动退出时只立即删除当前浏览器对应的当前 Session 记录，不批量结束其他浏览器或设备上的会话。
- 在基础认证之上实现注册和邮箱验证。
- 不引入 Devise、OAuth 或第三方登录。
- 邮箱验证链接有效期为 **15 分钟**。
- 忘记密码重置链接有效期为 **30 分钟**，同一账户只有最新链接有效，成功使用后立即失效且不能重复使用；密码重置令牌与邮箱验证令牌是不同的业务令牌。
- 邮箱验证成功和密码重置成功后均返回登录页，由用户手动登录，不自动创建登录会话。
- 忘记密码重置成功后撤销该账户的全部现存 Session；已登录用户修改密码成功后保留当前 Session，撤销其他 Session。

### 6.1 重新发送验证邮件

重新发送验证邮件支持两个入口，共用同一后端流程：

1. 注册结果页可以直接重新发送；待验证邮箱暂存在加密的浏览器 Session 中。
2. 用户也可以重新输入邮箱请求发送。

两个入口使用相同的令牌流程和限流统计。无论邮箱是否存在，都执行相同的限流判断和对外结果反馈，避免泄露账户状态。

验证令牌与限流规则：

- 新令牌保存且邮件任务实际入队成功后，先前令牌立即失效，同一时间只有最新验证链接有效；
- 验证链接成功使用后立即失效，不能重复使用；
- 邮件任务入队失败时保留当前仍有效的旧令牌；入队后投递失败不恢复旧令牌，通过重试或重新发送恢复；
- 同一邮箱两次发送至少间隔 60 秒，同一邮箱在 15 分钟内最多重新发送 3 次；
- 同一 IP 在 15 分钟内最多提交 10 次重新发送请求；
- 邮箱和 IP 限流按重发尝试计数，包括邮件任务入队失败的尝试；
- 不另外把浏览器 Session 作为独立限流维度；注册结果页直接重发与重新输入邮箱重发共用上述统计。

**已确认业务与风险边界**：`deliver_later` 的切换点是“新令牌保存且发送任务实际入队成功”，入队不等于送达。开发进程退出可能丢失内存队列任务，该风险已由用户接受；入队后失败不恢复旧链接。具体事务、Job 协作和故障处理协议见 [database-design.md](database-design.md) 第 14.3 节。M2-A～C 已依次验证令牌与限流基础、真实签发与入队切换、孤立 Job、并发重发、worker 状态重检及正式页面链路；这些是本地工程验证事实，不代表生产投递、生产队列或阶段 6 用户验收已经完成。

### 6.2 个人数据授权

- 注册、登录、邮箱验证、验证邮件重发和忘记密码等账户入口允许匿名访问；
- 所有 Observation 必须属于 User。
- 观察历史、详情、编辑、预览和鸟种识别都要求登录；读取、编辑和更新观察记录时必须从 `Current.user.observations` 开始查找，子对象只能通过已授权的 Observation 访问。
- 浏览器提交的 User、所有者字段或不属于该 Observation 的子对象 ID 一律忽略或拒绝；记录不存在和记录属于其他用户对外采用相同的 not-found 行为。
- 页面是否隐藏按钮不构成授权，所有状态变更端点都必须执行服务端授权和 CSRF 防护。
- MVP 不引入角色权限系统或管理员授权框架。

### 6.3 注册、验证与登录请求流程

- 已存在规范化邮箱再次注册时不创建第二个 User，注册动作也不自动重发验证邮件；对外只提供登录和重新验证入口，不能泄露账户是否已验证。
- 注册已创建未验证 User、但邮件任务未能成功入队时，保留该 User、不创建 Session，并进入可由统一重发流程恢复的结果状态。重发按 6.1 节的实际入队切换规则处理。
- 验证链接的第一次 GET 只检查令牌。有效时显示带脱敏邮箱的确认页；用户 POST 确认时再次校验令牌，并在一个原子操作中更新 User 验证状态、使令牌失效。链接扫描器仅访问 GET 不得完成验证。
- 过期、无效、已使用、已被替换的令牌不改变账户；结果页可提供重新发送入口。验证成功返回登录页并显示成功提示，但不创建 Session。
- 邮箱不存在或密码错误使用同一通用登录失败结果。密码正确但 User 未验证时可以明确提示验证并提供重发入口，但不创建 Session；流程可使用加密浏览器临时状态衔接待验证邮箱，完整邮箱不得出现在 URL。
- 主动登录成功进入观察历史；因访问受保护页面而登录时，可以返回经过校验的站内相对路径。外部、无效或缺失返回地址统一回到观察历史，避免开放重定向。

### 6.4 Session 恢复与退出

- 每次受保护请求都必须用 Cookie 定位数据库 Session，并重新检查其存在性、撤销状态和固定 30 天绝对有效期；普通访问不滑动续期。
- Cookie 缺失、Session 不存在、已撤销或已过期时清理当前 Cookie，并按未登录处理。受保护页面进入登录流程，公开页面不强制跳转。
- 已登录用户访问登录或注册页时进入观察历史。退出操作使当前数据库 Session 失效并清理当前 Cookie，之后返回登录页显示成功反馈；其他浏览器或设备的 Session 不受影响。
- 退出或撤销立即物理删除 Session；过期后即使记录尚未清理也不能认证，次日清理。Session 不保存 IP 或 User-Agent，其他保留规则见 6.8 节。

### 6.5 观察保存、预览与并发边界

- 打开新建页不创建数据库记录。正式保存从 `Current.user` 构建 Observation，服务器重新校验配置稳定键、部位适用性、最低保存条件、行动位置数量与唯一性。
- Observation、PartImpression 和 ActivityLocationSelection 的新建或编辑在同一数据库事务中整体成功或失败；失败时数据库不保留部分结果。首次保存成功后重定向到详情页，避免刷新重复提交。
- 编辑时清空部位全部有效内容会删除该 PartImpression；存在内容但缺少确定程度时整个提交失败。取消编辑丢弃浏览器工作状态并返回详情页。
- 预览只读取未保存表单数据来生成 SVG 与摘要，不写数据库，也不要求最低保存条件已经满足；无效配置键或不适用组合不得进入派生结果。正式保存必须重新执行服务端校验。
- 同一业务范围内，旧页面不能静默覆盖较新提交。Observation 编辑与 BirdIdentification 是两个独立并发范围；`database-design.md` 已形成独立版本与行锁的工程设计基线，实际约束和并发行为须随 Migration 与业务实施验证，不视为用户逐字段确认或已完成实现。
- MVP 暂不要求服务端幂等键；先使用浏览器提交锁和成功后重定向降低重复提交风险，并在真实并发测试后决定是否需要加强。

### 6.6 鸟种识别命令边界

- 添加候选、确认最终鸟名以及不需要选择保留方案的撤销确认是立即生效命令；删除候选和修改最终鸟名是暂存后明确保存的命令。存在未保存的暂存修改时，必须先保存或放弃，才能执行立即生效命令。
- 每个命令都重新校验 Observation 所有权、名称清理结果、候选唯一性、最多三个候选及派生状态；一次命令在事务中完整成功或完全失败，并发请求不得突破上限。
- 最终鸟名仍在候选中时撤销直接生效。最终鸟名不在候选中时必须由用户选择是否保留；选择保留且候选已满时必须明确选择替换对象，服务器不得静默删除候选。
- “确认依据”字段已明确不进入当前 MVP，不创建对应持久化字段。

### 6.7 服务端信任边界

- 所有浏览器输入都必须在服务器重新校验；前端 `required`、禁用按钮、隐藏字段和 Stimulus 状态只用于体验，不能替代业务校验或授权。
- 所有者、账户验证状态、密码摘要、Session 到期时间、首次成功保存时间、系统时间戳和派生识别状态由服务器控制。SVG、文字摘要和整体有效性由可信结构化数据计算。
- 配置稳定键必须来自当前版本允许的集合，并验证其身体部位适用性。日志不得记录密码、原始令牌或 Cookie；Cookie 只保存不透明 Session 定位值，不能成为登录事实来源。

### 6.8 敏感数据与保留期限

- 验证与密码重置令牌在业务数据库中只保存摘要，不保存可直接使用的原始令牌；邮件任务中必要的敏感运行时载荷与日志防护由 `database-design.md` 第 14～15 节承接，不把业务表摘要要求误读为邮件无需传递令牌。
- 邮箱／IP 限流主体使用带密钥摘要；请求尝试记录保留 24 小时，不把登录 Session 增加为独立限流维度。
- 两种失效令牌保留 7 天后清理；清理后旧链接统一显示无效，不再保留具体历史失效原因。
- 退出／撤销的 Session 立即删除，过期 Session 次日清理；有效性检查不等待清理任务。
- 账户与 Observation 不自动删除；不因此新增账户注销、观察删除、审计或版本历史功能。

以上为用户已确认的安全与生命周期边界；清理执行方式、索引、并发保护与 Migration 映射由 `database-design.md` 负责。M1 已验证认证基础中的当前 Session 退出删除及到期拒绝；M2-C 已实现并机械验证过期 Session 次日维护、验证令牌与限流数据清理以及正式页面退出流程。生产环境的调度方式仍留到部署阶段。

## 8. 显示语言与时区

- 使用 Rails I18n，支持 `zh-CN` 和 `ja`。

## 10. 最小数据对象与关系

以下保留六个核心对象的概念起点，不是当前数据库的实际 Schema；完整 10 实体 ER 图、物理设计和 Migration 映射见 `database-design.md`。M1 两表加上 M2-A 验证令牌、限流主体和尝试记录三表已落地，M2-B／C 没有新增业务表；具体五表清单见该文档第 9 节，其余结构仍为设计基线：

```text
User
├─ has_many Session
└─ has_many Observation
   ├─ has_many PartImpression
   ├─ has_many BirdCandidate
   └─ has_many ActivityLocationSelection
```

- **User**：邮箱、密码摘要、邮箱验证状态及账户时间信息。
- **Session**：登录会话，属于一个 User。
- **Observation**：属于一个 User，保存轮廓稳定键、首次保存时间、行为文字和最终鸟名等观察级数据。
- **PartImpression**：属于一个 Observation；每个实际记录的身体部位最多一条，保存部位键、主色键、补充色键、特征键、自由文字和确定程度。
- **BirdCandidate**：属于一个 Observation，保存一个用户自由输入的候选鸟名；业务规则限制最多三条。
- **ActivityLocationSelection**：属于一个 Observation，保存一个行动位置稳定键；业务规则限制最多两条。

轮廓、颜色、花纹／特征、行动位置及 SVG 映射属于受版本控制的策划配置，使用稳定键引用，不建立数据库字典表或 MVP 管理后台。

识别状态由候选鸟名和最终鸟名计算，文字摘要和 SVG 由结构化数据生成；这三类派生结果不单独持久化。

### 10.1 数据状态分类

- **数据库持久化**：User、Session、邮箱验证和密码重置业务状态与令牌摘要、限流证据、Observation、PartImpression、ActivityLocationSelection、候选鸟名和最终鸟名。具体映射见 `database-design.md`；M1 与 M2-A～C 已实现账户／Session、邮箱验证、数据库限流、注册发信、正式账户页面和维护清理，密码辅助、观察及识别流程仍未实施。
- **请求时派生**：识别状态、SVG、缩略图、文字摘要和观察记录整体有效性；这些结果不得作为新的事实字段持久化。
- **版本控制配置**：轮廓、颜色、花纹／特征、行动位置及 SVG 映射的稳定键与展示配置；它们不是用户业务数据。
- **仅浏览器临时状态**：未提交表单、预览输入、当前候选选择、暂存删除或改名、dirty 状态、经过校验的安全返回路径和待验证邮箱流程状态；不能误写入正式记录或恢复登录身份。
- **敏感运行时数据**：邮件任务参数和令牌相关信息只在完成任务所需的最小范围内传递，不写入普通日志或前端可见状态。

### 15.2 延后确认或验证

- **本地执行与生产安全分开处理**：本地不再以“关闭证书验证／更换 Oracle 客户端”二选一作为连接前置条件；这两项本轮均未采用，不表示用户正式否决。沙箱下同类错误可申请获批准的非沙箱对照；生产 TLS 身份验证、CA 和部署配置仍未确定，不得把本地加密连接成功当作生产安全验收。
- MySQL 5.7 备份是否以及何时进行隔离恢复演练；
- MySQL 8.4 旧初始化目录和安装文件是否清理；
- 生产托管平台、生产 MySQL 方案、邮件服务供应商、发件域名、Secrets、CI、生产备份、监控和告警方案；
- 后续纵向切片的边界和先后顺序。

当前技术路线确认到此为止。以上未确认事项按各自阶段延后处理，不得在正式决定前自行补全；生产与部署事项继续延后到本地 MVP 闭环验收之后。
