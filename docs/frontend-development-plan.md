## 2. 目标与边界

### 2.1 本计划的完成目标

- 完成高保真基线中的 14 个 MVP 用户页面或流程状态；
- 使用 Rails Views、ERB、HTML、CSS、Rails I18n，以及必要的 Turbo、Stimulus 或少量普通 JavaScript；
- 简体中文和日文页面均可渲染；
- 主流程可通过真实 Rails 链接和本地交互连续检查；
- 完成桌面和移动端尺寸的浏览器验证；
- 为页面渲染、导航与重要局部交互提供自动化测试。

### 2.2 当前不包含

- 登录、注册、认证、邮件发送或密码更新的后端实现；
- Model、Migration、Schema 或业务数据持久化；
- 将预览示例数据升级为正式鸟类数据或业务配置；
- 营销首页、公开主页、社交、地图、推荐、管理员和其他非 MVP 页面；
- 内部“设计系统”参考页作为用户页面交付项；
- React、Vue、Tailwind、独立 SPA 或新的前端构建体系。

### 2.3 静态交互原则

- 表单可以填写和展示状态，但不向业务端点提交；
- 导航按钮应尽量连接到实际预览路由，不使用无效 `href="#"`；
- 轮廓选择、标签选择、编辑部位切换和确认对话框等局部行为可以使用 Stimulus；
- 浏览器刷新后允许预览状态重置，不要求持久化；
- 所有预览路由继续限制在 Rails 本地环境中。

## 5. 分阶段实施计划

### 阶段 1：账户辅助正向流程

**目标**

- 补齐忘记密码申请、设置新密码和密码重置成功；
- 将登录页“忘记密码”入口接入完整静态流程；
- 保持重置成功后返回登录且不自动登录的页面表达。

**预计涉及**

- 预览路由和 Controller action；
- 3 个新 ERB 页面；
- 登录页导航；
- 中日文 I18n；
- 账户页面样式和集成测试。

**完成标准**

- 3 个页面在两种语言下均可渲染；
- 登录到密码重置成功再返回登录的流程连通；
- 表单保持静态且没有业务提交地址；
- 320px、390px 和桌面尺寸无明显溢出；
- 自动化测试和浏览器检查通过。

**实施结果（2026-08-15）**

状态：`待验收`

实际修改：

- 新增忘记密码申请、设置新密码和密码重置成功 3 个 ERB 页面；
- 新增 3 个本地预览路由与 Controller action；
- 登录页“忘记密码”接入预览流程；
- 补齐简体中文和日文文案；
- 扩展静态预览集成测试；
- 复用现有 B′ 账户组件和 CSS，本阶段没有修改样式文件。

验证结果：

- 目标集成测试：6 tests、165 assertions、0 failures、0 errors、0 skips；
- RuboCop：26 files、0 offenses；
- Brakeman：79 checks、0 errors、0 security warnings；
- 320px 简体中文：无横向溢出，表单宽度和触控区域正常；
- 390px 简体中文：登录至重置成功的完整预览跳转通过；
- 390px 日文：无缺失翻译或横向溢出，输入框和按钮高度 48px，预览链接高度 44px；
- 1440px 桌面：App 页面保持 410px 居中容器，无横向溢出；
- 浏览器 Console：0 warnings、0 errors；
- Rails 请求：全部返回 200，Active Record 查询数为 0。

与高保真基线的差异：

- 因为当前只实现静态前端，发送邮件和更新密码按钮不会提交；
- 使用独立的“仅预览”链接进入下一流程状态，避免把静态按钮表现成已接通后端；
- 未实现链接失效、发送失败和频率限制等尚未确认的异常状态。

### 阶段 2：非空观察历史

**目标**

- 完成非空历史页和记录卡片组件；
- 展示待确认、候选中、已确认三种状态；
- 候选中记录不在历史卡片显示候选鸟名；
- 已确认记录显示最终鸟名；
- 接通历史、详情、新建观察和设置导航。

**设计依赖**

- 记录卡中的鸟名、时间和摘要只使用预览示例；
- 底部导航最终图标仍待确认，当前只按基线实现。

### 阶段 3：两层轮廓选择

**目标**

- 实现第一层视觉大组；
- 实现第二层具体轮廓；
- 实现“没有合适的轮廓”兜底项；
- 提供选中、未选中、返回上一层和继续状态。

**技术工作**

- 在确有交互需要时补齐 Rails importmap 和 Stimulus 标准入口；
- 使用 Rails 原生 SVG/HTML，不引入 Canvas 或外部图形框架。

**设计依赖**

- 正式大组、轮廓名称、数量和排序尚未确认；
- 页面只能使用明确标记的预览示例，不生成正式配置。

### 阶段 4：观察记录编辑

本阶段体量较大，拆成三个连续小批次。

#### 阶段 4A：编辑器页面骨架

- 标准侧面鸟体图区域；
- 头部、胸腹、翅膀和尾部 Tab；
- 颜色、补充色、特征、确定程度和自由文字控件；
- 行动位置与行为补充区域；
- 固定保存区域和响应式布局。

#### 阶段 4B：局部交互与预览

- 自由切换身体部位；
- 单选和最多双选控制；
- 有记录和未记录部位状态；
- 静态 SVG 印象图和文字摘要更新演示。

#### 阶段 4C：保存与离开状态

- 未满足最低保存条件时的禁用状态；
- 有效轮廓加至少一个有效部位后的可保存状态；
- 未保存修改离开时的二次确认；
- 继续编辑和放弃修改两个操作。

**设计依赖**

- 正式颜色、花纹或特征、行动位置名单尚未确认；
- 保存提示和未保存确认框的最终细节仍待 UI Designer 确认。

### 阶段 5：观察记录详情与鸟种状态

**目标**

- 展示抽象图、摘要、各部位确定程度、行动位置和行为；
- 覆盖待确认、候选中和已确认三个详情状态；
- 展示最多三个候选鸟名的增加、选择和删除状态；
- 展示选择候选、输入其他最终鸟名、修改和撤销确认的页面状态；
- 接通返回历史和编辑记录。

**设计依赖**

- 候选管理、最终确认和撤销确认的最终控件细节仍待确认；
- 静态实现不保存候选或最终鸟名。

### 阶段 6：设置、修改密码与导航闭环

**目标**

- 设置页显示只读邮箱；
- 提供简体中文和日文选择，不提供“跟随系统”；
- 提供修改密码入口和退出登录入口；
- 完成修改密码页面；
- 让历史、详情、设置的底部导航全部可用；
- 确认登录、注册、轮廓选择和编辑页不显示底部导航。

### 阶段 7：完整性与回归

**目标**

- 检查全部 14 个页面的双语内容和链接；
- 覆盖基线已确认的空、禁用、选中、结果和对话框状态；
- 在已有设计依据范围内补齐表单错误、无效输入和边界状态；
- 检查标题层级、Label、ARIA、焦点顺序、键盘操作和触控区域；
- 检查 320px、390px 和桌面尺寸；
- 检查长日文、软键盘、固定底栏和滚动区域；
- 运行完整前端相关测试、RuboCop 和 Brakeman。

**完成边界**

账户异常反馈、链接失效、频率限制等尚无最终 UI 设计的状态，不得由开发 Agent 擅自定稿。若阶段 7 开始时仍无确认设计，应记录为设计阻塞，而不是自行补成正式设计。

## 6. 每阶段工作方式

开始每个阶段前：

1. 重新检查 Git status、未暂存 diff 和暂存区 diff；
2. 给出本阶段简短计划；
3. 列出拟修改文件及用途；
4. 说明是否涉及未确认设计；
5. 说明测试和浏览器验证方案。

完成每个阶段后：

1. 将阶段状态先更新为“待验收”；
2. 记录实际修改文件；
3. 记录实际运行命令；
4. 记录测试数量、failures、errors 和 skips；
5. 记录桌面和移动端浏览器验证结果；
6. 记录与高保真基线的差异及原因；
7. 记录已知覆盖缺口和未解决依赖；
8. 用户验收后将阶段状态更新为“已完成”；
9. 未经用户明确要求，不执行 `git add`、`git commit` 或推送。

## 7. 通用验证方案
